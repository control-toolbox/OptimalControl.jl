From Hamiltonians ​

The constructors on this page build a flow without an optimal control problem: from a Hamiltonian, a Hamiltonian vector field, a pseudo-Hamiltonian and a control law, or a plain vector field. They are the building blocks From an OCP is made of, and they are useful when you have worked out the Hamiltonian yourself.

julia
using OptimalControl
using OrdinaryDiffEqTsit5

From a Hamiltonian ​

Give ; its Hamiltonian vector field    is computed by automatic differentiation:

julia
H(x, p) = p[1] * x[2] + p[2]^2 / 2

f_h = Flow(Hamiltonian(H))
xf, pf = f_h(t0, x0, p0, tf)
([-4.158277980903794e-16, 5.038973481527467e-15], [12.0, -5.999999999999998])

A Hamiltonian is H(x, p) by default. If it depends on time, write H(t, x, p) and declare it with Hamiltonian(H; is_autonomous=false); if it depends on a variable, H(x, p, v) with is_variable=true. Without the declaration, the call fails with a MethodError.

From a Hamiltonian vector field ​

Give directly, as a function returning the pair . No automatic differentiation is involved:

julia
Hv(x, p) = ([x[2], p[2]], [0, -p[1]])

f_hv = Flow(HamiltonianVectorField(Hv))
f_hv(t0, x0, p0, tf)
([-4.158277980903794e-16, 5.038973481527467e-15], [12.0, -5.999999999999998])

From a pseudo-Hamiltonian and a control law ​

Give and the law : the flow is the one of  , differentiated through the law by automatic differentiation. This is what From an OCP does, with the pseudo-Hamiltonian read from the problem.

julia
Hp(x, p, u) = p[1] * x[2] + p[2] * u - u^2 / 2
law(x, p) = p[2]

f_hp = Flow(PseudoHamiltonian(Hp), DynClosedLoop(law))
f_hp(t0, x0, p0, tf)
([-4.158277980903794e-16, 5.038973481527467e-15], [12.0, -5.999999999999998])

hamiltonian_type=:partial freezes the control instead of differentiating through the law (see Total or partial Hamiltonian).

From a vector field ​

A flow of the state alone,  , or when declared with is_autonomous=false. With the optimal control    written as a function of time, the state reaches the target:

julia
f_x = Flow(VectorField((t, x) -> [x[2], 6 - 12t]; is_autonomous=false))
f_x(t0, x0, tf)
2-element Vector{Float64}:
 -2.7259067227910837e-15
 -9.06882116070656e-16

To simulate a control system under a given control, open-loop or feedback, see Simulation.

From a SciML problem ​

An ODEFunction or an ODEProblem of the SciML ecosystem can be used directly, with OrdinaryDiffEqTsit5 alone. The parameter p of the SciML function f!(dx, x, p, t) is the variable of the flow, passed with the keyword variable. Here    :

julia
rhs!(dx, x, p, t) = (dx[1] = -p * x[1]; nothing)

f_ode = Flow(ODEFunction(rhs!))
f_ode(0, [1.0], 1; variable=2)   # exp(-2)
0.13533528340900092

So the keyword is required even when the function does not use p: pass variable=nothing. Without it, the call raises an error:

julia
julia> f_ode(0, [1.0], 1)
PreconditionError → top-level scope, REPL[1]:2
│
│  variable not provided for a NonFixed flow
│
│  Reason   flow depends on an extra variable parameter but none was given
│
│  Context  call — NonFixed flow with missing variable
│  Hint     Pass `variable=v` when calling the flow
└─

An ODEProblem works the same way:

julia
f_prob = Flow(ODEProblem(rhs!, [1.0], (0.0, 1.0), 2.0))
f_prob(0, [1.0], 1; variable=2)
1-element Vector{Float64}:
 0.13533528340900092

Hamiltonian, HamiltonianVectorField, PseudoHamiltonian, PseudoHamiltonianVectorField and VectorField take the keywords is_autonomous=false and is_variable=true for a function of time or of a variable. Every Flow takes the integrator options of Flows overview. Called on a time span, f((t0, tf), x0, p0) returns a trajectory: see Simulation.
