From an OCP ​

This is the main path of the indirect method. You have worked out, from the maximum principle, the control law that maximises the pseudo-Hamiltonian, and you want the Hamiltonian flow it defines. Flow(ocp, law) reads the dynamics and the cost from the problem, so you only write the law. The notation is the one of Notation and conventions.

julia
using OptimalControl
using OrdinaryDiffEqTsit5

t0 = 0
tf = 1
x0 = [-1, 0]

ocp = @def begin
    t ∈ [t0, tf], time
    x = (q, v) ∈ R², state
    u ∈ R, control
    x(t0) == x0
    x(tf) == [0, 0]
    ẋ(t) == [v(t), u(t)]
    0.5∫(u(t)^2) → min
end

Passing a typed law ​

Flow(ocp, law) wraps the function in a DynClosedLoop law: a feedback on the state and the costate. Writing it explicitly gives the same flow:

julia
f_typed = Flow(ocp, DynClosedLoop((x, p) -> p[2]))
xf_typed, _ = f_typed(t0, x0, p0, tf)
isapprox(xf_typed, xf; atol=1e-12)
true

The two other kinds of law, ClosedLoop(x -> …) and OpenLoop(t -> …), do not involve the costate: they build a flow of the state alone, to simulate a given control (see Simulation).

Problems with a variable ​

With an optimisation variable , the control law takes it as a third argument: u(x, p, v), or u(t, x, p, v) for a non-autonomous problem. Take a problem whose variable is the final time:

julia
ocp_v = @def begin
    tf ∈ R, variable
    t ∈ [0, tf], time
    x ∈ R, state
    u ∈ R, control
    tf ≥ 0
    x(0) == 0
    x(tf) == 1
    ẋ(t) == tf * u(t)
    tf + 0.5∫(u(t)^2) → min
end

fc = Flow(ocp_v, (x, p, tf) -> tf * p)

The costate of the variable ​

With variable_costate=true, the point call also integrates the costate of the variable,    from  , and returns three values, (xf, pf, pvf). This is what the transversality condition on the variable needs (see Notation and conventions).

Take a harmonic oscillator whose pulsation is optimised, with the cost  , and solve it with the direct method first:

julia
using NLPModelsIpopt

ocp_ω = @def begin
    ω ∈ R, variable
    t ∈ [0, 1], time
    x = (q, v) ∈ R², state
    u ∈ R, control
    x(0) == [1, 0], (start)
    q(1) == 0
    ẋ(t) == [v(t), -ω^2 * q(t) + u(t)]
    ω^2 + 0.5∫(u(t)^2) → min
end

sol_ω = solve(ocp_ω; grid_size=500, display=false)
ω_opt = variable(sol_ω)
p0_ω = dual(sol_ω, ocp_ω, :start)   # the initial costate (see the Solution page)
ω_opt, p0_ω
(0.653763301228066, [-2.059403829775405, -2.413460259562427])

Then integrate the flow from this initial costate, with the costate of :

julia
fω = Flow(ocp_ω, (x, p, ω) -> p[2])
xf_ω, pf_ω, pω = fω(0, [1, 0], p0_ω, 1; variable=ω_opt, variable_costate=true)
pω, -2ω_opt
(-1.307528321033575, -1.307526602456132)

Total or partial Hamiltonian ​

The keyword hamiltonian_type chooses how the flow is built from and the law :

  • :total, the default, integrates the Hamiltonian system of  , differentiating through the law:    and    ;

  • :partial takes the partial derivatives of with the control frozen at the value of the law:  ,   , at  .

The two differ by the terms in . These vanish when   along the law, as for a control that maximises inside the control set, and also where the law is locally constant, as for bang–bang or saturated controls. So for an optimal control law the two give the same flow. For another law, they do not, and the state of :partial is the one the law actually drives,  : use :partial to simulate a given feedback.

Take the law   , which does not maximise :

julia
law(x, p) = p[2] + 1

xf_total, _ = Flow(ocp, law; hamiltonian_type=:total)(t0, x0, p0, tf)
xf_partial, _ = Flow(ocp, law; hamiltonian_type=:partial)(t0, x0, p0, tf)
xf_total, xf_partial
([6.943952265347772e-16, 5.038973481527467e-15], [0.4999999999999938, 1.0000000000000056])

With :partial, the state is driven by     , which overshoots the target. With :total, the flow is the one of         . It differs from the optimal    by a constant, so it has the same Hamiltonian vector field, and it reaches the target as the optimal law does. This is a property of this example, not of :total.

What comes back ​

The point call f(t0, x0, p0, tf) returns (xf, pf), or (xf, pf, pvf) with variable_costate=true. The trajectory call f((t0, tf), x0, p0) returns a Solution, as solve does: state, costate, control, objective and plot work on it, but it has no multipliers (see Solutions from a flow).

julia
sol = f((t0, tf), x0, p0)
objective(sol)
5.999999999999946

This is specific to flows built from a problem with a law of the state and the costate. The other flows, such as Flow(ocp, OpenLoop(…)) or Flow(Hamiltonian(H)), return their own trajectories: see What a flow returns.
