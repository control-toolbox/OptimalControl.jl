Model a problem as you write it on paper, solve it by direct and indirect methods, on CPU and GPU.

Close to the mathematics

The @def macro reads like the problem on paper. A functional API builds the same model from plain functions.

Direct methods

Discretise, build the NLP with ADNLPModels or ExaModels, and solve it with Ipopt, MadNLP, Knitro and others.

Indirect methods

Hamiltonian flows built from the problem, concatenated arc by arc, and shooting started from the direct solution.

GPU

The same problem, solved on an NVIDIA GPU with ExaModels and MadNLP.

Geometry

Lifts, Lie and Poisson brackets and the @Lie macro, to compute singular controls.

An ecosystem

Tutorials, a collection of problems, benchmarks, and applications built on the package.

Installation ​

julia
using Pkg
Pkg.add("OptimalControl")

A solver, plotting and the ODE integrators of the indirect method are separate packages, loaded only when you use them: see Installation.

Basic usage ​

Let us model, solve and plot a simple optimal control problem.

julia
using OptimalControl
using NLPModelsIpopt  # Ipopt solver extension (needed for solve)
using Plots           # plotting extension (needed for plot)

ocp = @def begin
    t ∈ [0, 1], time
    x ∈ R², state
    u ∈ R, control
    x(0) == [-1, 0]
    x(1) == [0, 0]
    ẋ(t) == [x₂(t), u(t)]
    ∫( 0.5u(t)^2 ) → min
end

sol = solve(ocp)
plot(sol)

That is the whole program — model, solve, plot. Each step has its own guide:

  • For more details about the example, see the energy minimisation page.

  • The @def macro defines the problem. See the abstract syntax guide.

  • The solve function has many options. See the solve overview.

  • The plot function is flexible. See the plot guide.
