Initial guess ​

Why the guess matters ​

The solver of the direct method finds a local solution, near where it starts. When the problem has several, the initial guess chooses which one it returns. Take a point that moves from   to with the least energy, around a disc of radius centred at : it can pass below the disc, or above it, a little longer.

julia
obstacle = @def begin
    t ∈ [0, 1], time
    x = (x₁, x₂) ∈ R², state
    u ∈ R², control
    x(0) == [-1, 0]
    x(1) == [1, 0]
    ẋ(t) == u(t)
    x₁(t)^2 + (x₂(t) - 0.1)^2 ≥ 0.25
    ∫(u₁(t)^2 + u₂(t)^2) → min
end

above = @init obstacle begin
    x₁(t) := -1 + 2t
    x₂(t) := sin(π * t)
end
below = @init obstacle begin
    x₁(t) := -1 + 2t
    x₂(t) := -sin(π * t)
end

sol_above = solve(obstacle; init=above, display=false)
sol_below = solve(obstacle; init=below, display=false)
objective(sol_above), objective(sol_below)
<< @example-block not executed in draft mode >>

Both solves succeed, on two different solutions. The one below the disc costs less: started above, the solver stays on the other side.

julia
ts = range(0, 1; length=200)
path(sol) = (t -> state(sol)(t)[1]).(ts), (t -> state(sol)(t)[2]).(ts)
θ = range(0, 2π; length=200)
plt = plot(0.5cos.(θ), 0.1 .+ 0.5sin.(θ); seriestype=:shape, fillalpha=0.2, label="obstacle",
           aspect_ratio=1, size=(600, 400))
plot!(plt, path(sol_above)...; label="started above")
plot!(plt, path(sol_below)...; label="started below")
<< @example-block not executed in draft mode >>
julia
@assert successful(sol_above) && successful(sol_below)                          # hide
@assert objective(sol_below) < objective(sol_above) - 0.5                       # hide
@assert state(sol_above)(0.5)[2] > 0.5 && state(sol_below)(0.5)[2] < -0.3       # hide
nothing                                                                         # hide
<< @example-block not executed in draft mode >>

The default guess, 0.1 everywhere, gives the better solution here too, in more iterations; on another problem it may not. A guess built from what you know of the solution, its shape or a solution of a nearby problem, is how you choose.

Two running examples ​

The rest of the page shows every way to write a guess, on two problems, to show both default and custom component labels:

julia
t0 = 0; tf = 10; α = 5

ocp1 = @def begin
    t ∈ [t0, tf], time
    x ∈ R², state
    u ∈ R, control
    x(t0) == [-1, 0]
    x₁(tf) == 0
    ẋ(t) == [x₂(t), x₁(t) + α * x₁(t)^2 + u(t)]
    x₂(tf)^2 + ∫(0.5u(t)^2) → min
end
nothing # hide
<< @example-block not executed in draft mode >>
julia
ocp2 = @def begin
    tf ∈ R, variable
    s ∈ [0, tf], time
    x = (q, v) ∈ R², state
    u ∈ R, control
    -1 ≤ u(s) ≤ 1
    tf ≥ 0
    q(0) == -1
    v(0) == 0
    q(tf) == 0
    v(tf) == 0
    ẋ(s) == [v(s), u(s)]
    tf → min
end
nothing # hide
<< @example-block not executed in draft mode >>

Component labels and time variable in @init

  • @init uses the labels declared in @def. For ocp1, you can use x, x₁, x₂ and u; for ocp2, x, q, v, u and tf.

  • When components are not named in @def (as in ocp1 with x ∈ R²), they receive default labels with subscripted indices, x₁, x₂, usable in @init like custom labels.

  • @init uses the time variable name of @def: t for ocp1 (x(t) := …), s for ocp2 (q(s) := …).

The default guess ​

With no initial guess, every component defaults to 0.1. To see it without solving, run with max_iter=0:

julia
sol_init = solve(ocp1; init=nothing, max_iter=0, display=false)
plot(sol_init, :state, :control; size=(800, 800))
<< @example-block not executed in draft mode >>

Solving with no guess at all, init=nothing, and init=() are all equivalent — all three skip straight to the default:

julia
sol = solve(ocp1; display=false)
println("no init:         ", iterations(sol), " iterations")

sol = solve(ocp1; init=nothing, display=false)
println("init=nothing:     ", iterations(sol), " iterations")

sol = solve(ocp1; init=(), display=false)
println("init=():          ", iterations(sol), " iterations")

The @init macro ​

@init builds an initial guess with the syntax label(t) := expression (functions of time) or label := value (for variables and aliases, which aren't functions of time):

julia
ig = @init ocp begin
    # specifications
end
ComponentFormExample
State / control, function of timelabel(t) := expressionu(t) := -0.2t
State / control, constantlabel(t) := value or label := valueu := 2
State / control, on a gridlabel(T) := data, T a time vectoru(T) := U
Variablelabel := valuetf := 2.0
Alias (local name)name = expressiona = 0.5

1-D components take a scalar (u(t) := 2), following the 1-D is a scalar rule; multi-D components take a vector (x(t) := [1, 2]).

The indexed syntax x[1](t) := ... is not supported — @init works at the level of declared labels, not array positions; use x₁(t) := ... or a component's own name instead.

Constant ​

julia
ig = @init ocp1 begin
    x(t) := [-0.2, 0.1]
    u(t) := -0.2
end

sol = solve(ocp1; init=ig, display=false)
println(iterations(sol), " iterations")
<< @example-block not executed in draft mode >>

Constants also accept the shorter form without the time argument (u := 2 instead of u(t) := 2):

julia
ig = @init ocp2 begin
    q := -0.2
    v := 0.0
    u := 0.1
    tf := 2.0
end

sol = solve(ocp2; init=ig, display=false)

Aliases ​

= (no time argument) defines a local alias, not a problem label:

julia
ig = @init ocp2 begin
    amplitude = 0.5
    φ = 2π * s
    q(s) := amplitude * sin(φ)
    v(s) := amplitude * cos(φ)
    u(s) := sin(amplitude)
    tf := 2.0
end

Cross-spec references ​

Specifications inside one @init block can reference each other, from top to bottom:

  • a reference only resolves to a label (or alias) defined earlier in the block;

  • substitution happens by name: the referenced label is replaced by its definition when the later expression is evaluated;

  • grid specs are not substituted (see the note below).

Temporal → temporal, and chains. v references q, and u references v, hence q:

julia
ig = @init ocp2 begin
    q(s) := sin(s)
    v(s) := 1.0 + q(s)      # references q
    u(s) := s + v(s)^2      # transitively references q via v
    tf := 2.0
end

sol = solve(ocp2; init=ig, display=false)
println(iterations(sol), " iterations")
<< @example-block not executed in draft mode >>

Constant → temporal. A function of time can use a constant defined earlier:

julia
ig = @init ocp2 begin
    q    := -1.0
    v(s) := q + sin(s)      # uses the constant value of q
    u(s) := 0.0
    tf   := 2.0
end

sol = solve(ocp2; init=ig, display=false)
println(iterations(sol), " iterations")
<< @example-block not executed in draft mode >>

Constant → constant. A constant can use another one, including between the components of a variable. Here the variable has two components, (tf, a), and the guess is read back with variable:

julia
ocp_var2 = @def begin
    w = (tf, a) ∈ R², variable
    t ∈ [0, 1], time
    x ∈ R, state
    u ∈ R, control
    x(0) == 0
    x(1) - a == 0
    ẋ(t) == u(t)
    ∫(0.5u(t)^2) → min
end

ig = @init ocp_var2 begin
    tf := 1.0
    a  := tf + 0.5
end

variable(ig)
<< @example-block not executed in draft mode >>

With aliases. Aliases (=) and references (:=) combine freely:

julia
ig = @init ocp2 begin
    A    = 2.0              # alias
    q(s) := A * sin(s)      # uses the alias
    v(s) := q(s) + 1.0      # references q
    u(s) := 0.0
    tf   := 2.0
end

sol = solve(ocp2; init=ig, display=false)
println(iterations(sol), " iterations")
<< @example-block not executed in draft mode >>

No substitution across grid specs

A grid spec (label(T) := data, see below) lives in a different evaluation context: it is not substituted into a spec written with the time variable, or vice versa. Keep one style per chain of references.

Vector initial guess (interpolated) ​

label(T) := data, with T a time vector, interpolates data onto the solve grid:

julia
T = [0.0, 5.0, 10.0]
X = [[-1.0, 0.0], [-0.5, 0.5], [0.0, 0.0]]
U = [0.0, -0.5, 0.0]

ig = @init ocp1 begin
    x(T) := X
    u(T) := U
end

sol = solve(ocp1; init=ig, display=false)
println(iterations(sol), " iterations")
<< @example-block not executed in draft mode >>

Different components can use different grids:

julia
Sq = [0.0, 1.0, 2.0]; Dq = [-1.0, -0.5, 0.0]
Sv = [0.0, 2.0];      Dv = [0.0, 0.0]
Su = [0.0, 1.0, 2.0]; Du = [0.0, 0.5, 0.0]

ig = @init ocp2 begin
    q(Sq) := Dq
    v(Sv) := Dv
    u(Su) := Du

end

sol = solve(ocp2; init=ig, display=false)

Mixing them ​

Constants, functions, and grids combine freely in one @init block:

julia
T = [0.0, 5.0, 10.0]
X = [[-1.0, 0.0], [-0.5, 0.5], [0.0, 0.0]]

ig = @init ocp1 begin
    x(T) := X               # grid
    u(t) := -0.2 * sin(t)   # function
end

sol = solve(ocp1; init=ig, display=false)
println(iterations(sol), " iterations")

Warm start from a solution ​

Pass a Solution directly — dimensions of state, control, and variable must match. This is the basis for discrete continuation:

julia
sol_init = solve(ocp1; display=false)
sol = solve(ocp1; init=sol_init, display=false)
println(iterations(sol), " iterations")
<< @example-block not executed in draft mode >>

Or extract functions from a solution and feed them through @init:

julia
x_fun = state(sol_init)
u_fun = control(sol_init)

ig = @init ocp1 begin
    x(t) := x_fun(t)
    u(t) := u_fun(t)
end

sol = solve(ocp1; init=ig, display=false)
println(iterations(sol), " iterations")
<< @example-block not executed in draft mode >>

state, costate and control on a solution return functions of time; variable returns the value of the variable (a scalar for a 1-D variable, a vector otherwise).

Without @init: a named tuple ​

init also accepts a named tuple with the fields state, control and variable, each a constant or a function of time (any subset of them):

julia
sol = solve(ocp2; init=(state=s -> [-1 + s, 0.0], control=0.1, variable=2.0), display=false)
println(iterations(sol), " iterations")
<< @example-block not executed in draft mode >>

Inspect or check a guess ​

Whatever you pass as init, solve turns it into an initial guess with build_initial_guess(ocp, init). You can call it yourself, and read the result back with state, control and variable, as on a solution. Components that are not specified take the default value 0.1:

julia
ig = build_initial_guess(ocp2, @init(ocp2, begin
    q(s) := sin(s)
    tf := 2.0
end))
state(ig)(0.5), control(ig)(0.5), variable(ig)
<< @example-block not executed in draft mode >>

The same holds for the output of @init itself, which is an initial guess already.

build_initial_guess also checks the guess against the problem: a component of the wrong dimension raises an IncorrectArgument. To check a guess before solving, build it:

julia
err = try
    build_initial_guess(ocp2, (state=[-1.0, 0.0, 0.0],))   # ocp2 has a 2-D state
    nothing
catch e
    e
end
err isa OptimalControl.IncorrectArgument
<< @example-block not executed in draft mode >>
julia
@assert err isa OptimalControl.IncorrectArgument # hide
nothing # hide
<< @example-block not executed in draft mode >>

Costate and multipliers ​

There is currently no way to seed the costate or the multipliers — only state, control, and variable accept an initial guess.

init or initial_guess ​

init is an alias for initial_guess; use whichever reads better, but not both in the same call. Passing both raises an IncorrectArgument "Conflicting aliases for the same option", in descriptive and explicit mode alike.
