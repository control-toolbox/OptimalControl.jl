Solve overview ​

solve is the entry point for the direct methods: transcribe the problem, hand it to an NLP solver, get a Solution back. This page shows the quickest way to call it, how to read what it prints, and the two ways to steer it away from its defaults.

The direct method ​

A direct method replaces the optimal control problem by a finite-dimensional one: a grid cuts the time interval, the unknowns are the values of the state and of the control on the grid, and the dynamics becomes the equations of an integration scheme between consecutive points. This gives a nonlinear program (NLP), solved by an NLP solver, Ipopt by default; its multipliers give the costate of the solution. The equations are on The direct method.

solve carries out these steps with three components: a discretizer (the grid and the scheme), a modeler that builds the NLP, and a solver. The rest of this section shows how to choose and configure them. Discretisation runs the steps one by one, and keeps the discretised problem and the NLP to inspect them or to hand them to another solver.

Quick start ​

julia
using OptimalControl
using NLPModelsIpopt

t0 = 0
tf = 1
x0 = [-1, 0]

ocp = @def begin
    t ∈ [t0, tf], time
    x = (q, v) ∈ R², state
    u ∈ R, control
    x(t0) == x0
    x(tf) == [0, 0]
    ẋ(t) == [v(t), u(t)]
    0.5∫(u(t)^2) → min
end

sol = solve(ocp)

Reading the display ​

Before running, solve prints the method it is about to use, then a Configuration box with one line per strategy: the discretizer, the modeler and the solver. Each line lists the options that differ from the strategy's defaults. Above, no option was passed, so the box only names the strategies. Pass some options, and they appear on the line of the strategy that receives them:

julia
sol = solve(ocp; grid_size=50, scheme=:trapeze, max_iter=100, print_level=0)
▫ This is OptimalControl 2.2.1-beta, solving with: collocation → adnlp → ipopt (cpu)

  📦 Configuration:
   ├─ Discretizer: collocation (grid_size = 50, scheme = trapeze)
   ├─ Modeler: adnlp
   └─ Solver: ipopt (max_iter = 100, print_level = 0)

The box now shows:

  • Discretizer: collocation, with grid_size = 50 and scheme = trapeze;

  • Modeler: adnlp, with no option of its own;

  • Solver: ipopt, with max_iter = 100 and print_level = 0.

Each option was sent to the strategy that declares it: this is the automatic routing described in Options. Some defaults depend on the :cpu/:gpu parameter; they are shown too, tagged [cpu-dependent] (or [gpu-dependent]). For instance, MadNLP's linear solver:

julia
using MadNLP
sol = solve(ocp, :madnlp; print_level=MadNLP.ERROR)
▫ This is OptimalControl 2.2.1-beta, solving with: collocation → adnlp → madnlp (cpu)

  📦 Configuration:
   ├─ Discretizer: collocation
   ├─ Modeler: adnlp
   └─ Solver: madnlp (linear_solver = MumpsSolver [cpu-dependent], print_level = ERROR)

Default values are not shown. To list every option of a strategy with its default, use describe, for instance describe(:ipopt) (see Options).

Turning the display off ​

julia
sol = solve(ocp; display=false)

It silences both the configuration box and the solver's own log. Useful once you trust a configuration and are solving in a loop, a test, or a script.

The defaults ​

Calling solve(ocp) with no strategy tokens is equivalent to:

julia
solve(ocp, :collocation, :adnlp, :ipopt, :cpu)

This quadruplet is the first entry of methods(), and completion always takes the first match, top to bottom (see Choosing a method for the full list and how partial descriptions are completed).

Two ways to steer it ​

solve can be pointed at a different strategy in two styles:

  • descriptive: symbolic tokens, e.g. solve(ocp, :madnlp) (see Choosing a method),

  • explicit: typed components, e.g. solve(ocp; solver=OptimalControl.MadNLP()) (see Explicit mode).

Use one style or the other in a call, not both: a typed component together with symbolic tokens is rejected.

julia> solve(ocp, :collocation; solver=OptimalControl.MadNLP())
ERROR: IncorrectArgument
│
│  Cannot mix explicit components with symbolic description
│
│  Got       explicit components + symbolic description (:collocation,)
│  Expected  either explicit components OR symbolic description
│
│  Context   solve function call
│  Hint      Use either solve(ocp; discretizer=..., modeler=..., solver=...) OR solve(ocp, :collocation, :adnlp, :ipopt)
└─

When it fails ​

A solve that does not converge still returns a Solution. Check it rather than assuming success. Here we stop Ipopt before its first iteration:

julia
sol = solve(ocp; max_iter=0, display=false, print_level=0)
@show successful(sol)              # did the solver report success?
@show status(sol)                  # a Symbol, e.g. :first_order, :max_iter
@show constraints_violation(sol)
successful(sol) = false
status(sol) = :max_iter
constraints_violation(sol) = 1.1

The solution holds the initial guess, which violates the boundary conditions. A converged solve reports successful(sol) == true, the status :first_order and a negligible violation:

julia
sol = solve(ocp; display=false, print_level=0)
@show successful(sol)
@show status(sol)
@show constraints_violation(sol)
successful(sol) = true
status(sol) = :first_order
constraints_violation(sol) = 2.220446049250313e-16
