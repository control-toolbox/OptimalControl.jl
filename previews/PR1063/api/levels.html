API levels ​

OptimalControl builds on several packages (see Ecosystem) and gives access to what a user needs from them at two levels. A third level holds what it uses internally. The lists below are generated from the package itself, and each name links to its documentation.

LevelReached asWhat
1. Exportedusing OptimalControl, then namethe vocabulary of the package: problems, solve, solutions, flows, geometry
2. QualifiedOptimalControl.Namestrategies (modelers, solvers, discretizer, AD backend), types, exceptions
3. Internalnot for usersthe modules of the packages OptimalControl builds on

Why these choices.

  • Exported: the names a user writes in every script, so that using OptimalControl is enough.

  • Qualified: the strategies have the names of the packages they rely on (Ipopt, MadNLP, DifferentiationInterface): exporting them would clash with these packages in the user's session. The exceptions are rarely written, only to check what a call raised, and the types mostly appear in signatures. Writing OptimalControl.Ipopt() says where the name comes from.

  • Internal: no module name is exported. @def, @init and @Lie work after import OptimalControl alone, so a user never needs CTModels or CTBase in scope.

Level 3: internal ​

The modules OptimalControl binds, for its own use. They are reachable as OptimalControl.Module, but a user should not need them.

ModuleWhy OptimalControl binds it
ADNLPModelsloaded to arm the :adnlp modeler (extension CTSolversADNLPModels)
CTBasestrategies, options, exceptions, the Data types of flows
CTDirectthe direct method: the Collocation discretizer
CTFlowsflows and their accessors
CTLiedifferential geometry: ad, Lift, Poisson, @Lie
CTModelsproblems, solutions, initial guesses, plots and I/O
CTSolversmodelers, NLP solvers, integrators
CommonSolvethe generic function solve
DifferentiationInterfacePkgthe package DifferentiationInterface, loaded to arm the AD of the geometry (extension CTBaseDifferentiationInterface)
DocStringExtensionsdocstrings
ExaModelsloaded for the :exa modeler
ForwardDiffloaded to arm the AD of solve (extension CTSolversForwardDiff)
LinearAlgebraloaded to arm the linear algebra of ExaModels
Reexportbuilds the exported names
